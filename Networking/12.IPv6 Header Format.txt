----------------------------------------------------------------------------------------------------
🛠️ DETAILED BREAKDOWN OF IPv6 HEADER FIELDS (Hinglish Notes)
----------------------------------------------------------------------------------------------------

1. FIXED BASE HEADER (40 Bytes Total):
   - IPv6 ke base header ka size **hamesha fixed (40 Bytes)** hota hai. 
   - Isme 8 fields hote hain (IPv4 mein 12-14 fields hote the, isiliye IPv6 routers par fast process hota hai).

2. ROW 1: BASIC METADATA & QOS
   - Version (4 bits): IP Version batata hai. IPv6 ke liye iski fixed value binary mein `0110` (6) hoti hai.
   - Priority / Traffic Class (8 bits): IPv4 ke 'Type of Service (ToS)' ki tarah packets ki priority (Quality of Service - QoS) maintain karta hai.
   - Flow Label (20 bits): Real-time audio/video flows ko identify karne ke liye use hota hai taaki saare packets same router path se jayein aur delay na ho.

3. ROW 2: LENGTH, NEXT HEADER & LIFETIME
   - Payload Length (16 bits): IP Base Header (40 Bytes) ke baad kitna extra data + extension headers hain, unka size bytes mein batata hai.
   - Next Header (8 bits): IPv4 ke 'Protocol' field ki tarah kaam karta hai. Batata hai ki is header ke baad kaun sa Extension Header hai ya kaun sa Upper-Layer Protocol (TCP/UDP) aayega.
   - Hop Limit (8 bits): IPv4 ke 'TTL (Time To Live)' ki tarah kaam karta hai. Har router par yeh 1 se kam hota hai. Jab 0 ho jata hai, packet drop ho jata hai loop se bachne ke liye.

4. ROW 3 & ROW 4: ADDRESSES
   - Source Address (128 bits / 16 Bytes): Packet bhejne wale (Sender) ka complete 128-bit IPv6 Address.
   - Destination Address (128 bits / 16 Bytes): Packet receive karne wale (Receiver) ka complete 128-bit IPv6 Address.

5. EXTENSION HEADERS:
   - Extra options (jaise Fragmentation, Security/IPSec, Routing) ko base header mein rakhne ke bajaye **Extension Headers** ke form mein alag se chain kiya jata hai.

1. VERSION (4 Bits):
   - Slide Text:
   - Hinglish Explanation:
     * Size: **4 bits** ka field hota hai.
     * Function: IP Version determine karta hai. IPv6 header ke liye iski value binary bit sequence **`0110`** (Dec: 6) hoti hai.

2. TRAFFIC CLASS (8 Bits):
   - Slide Text:
   - Hinglish Explanation:
     * Size: **8 bits** ka field hota hai.
     * Purpose: Packet ki priority/class set karta hai (Bilkul IPv4 ke 'Type of Service / ToS' field ki tarah).
     * Router Handling: Network routers ko batata hai ki kaun sa traffic pehle process karna hai (e.g., Real-time voice/video vs normal web browsing).
     * CONGESTION RULE (Exam Imp): Network par traaffic congestion (jaam) hone par routers sabse **kam priority wale packets (least priority)** ko sabse pehle discard/drop kar dete hain!

3. FLOW LABEL (20 Bits):
   - Slide Text:
   - Hinglish Explanation:
     * Size: **20 bits** ka field hota hai.
     * Purpose: Source host iska use ek hi communication stream/flow (jaise continuous video stream) ke saare packets ko same unique tag label dene ke liye karta hai.
     * Re-ordering Prevention: Is label se routers ko pata rehta hai ki yeh ek hi flow ka part hain, jisse packets alag-alag paths se bhatak kar **out-of-order (aage-piche) deliver nahi hote**.
     * Special Handling: Intermediate routers ko batata hai ki in packets ko special treatment (Non-default QoS ya Real-time streaming preference) di jaye.

4. PAYLOAD LENGTH (16 Bits):
   - Slide Text:
   - Hinglish Explanation:
     * Size: **16 bits** ka field hota hai.
     * Formula: 
       $$\text{Payload Length} = \text{Data Size} + \text{Extension Headers Size}$$
       *(Note: IPv4 ki tarah isme Base Header ka 40 Bytes add NAHI hota, sirf base header ke aage ka data include hota hai).*
     * JUMBO PAYLOAD RULE (Exam Special):
       - Standard 16-bit field ki max value $2^{16} - 1 = 65,535\text{ bytes}$ hoti hai.
       - Agar payload ka size **65,535 bytes se bada** ho jaye, toh IPv6 **Jumbo Payload Option (Jumbogram)** Extension Header ka use karta hai!


5. NEXT HEADER (8 Bits):
   - Slide Text:
     * "8 bits"
     * "indicates type of extension header (if present) immediately following the IPv6 header"
     * "In some cases indicates the protocols contained within upper-layer packet, such as TCP, UDP."
   - 💡 Hinglish Explanation:
     * Size: **8 bits** ka field hota hai.
     * Dual Role (Do Kaam):
       1. Extension Header Pointer: Batata hai ki Base IPv6 Header ke immediately baad kaun sa **Extension Header** (jaise Routing, Hop-by-Hop, Fragment) laga hua hai.
       2. Protocol Identifier: Agar koi extension header nahi hai, toh yeh IPv4 ke 'Protocol' field ki tarah kaam karta hai aur batata hai ki Upper-Layer Payload mein kaun sa protocol (**TCP = 6**, **UDP = 17**) packed hai.

6. HOP LIMIT (8 Bits):
   - Slide Text:
     * "8-bit"
     * "Analogous to TTL"
     * "indicates the maximum number of intermediate nodes IPv6 packet is allowed to travel."
   - 💡 Hinglish Explanation:
     * Size: **8 bits** ka field hota hai.
     * IPv4 Equivalent: Yeh IPv4 ke **TTL (Time To Live)** field ke bilkul barabar (analogous) hota hai.
     * Lifetime Control: Iska main kaam yeh decide karna hai ki packet network par maximum kitne intermediate routers (nodes/hops) cross kar sakta hai.
     * Working Mechanism: Jab bhi packet kisi router se guzarta hai, Hop Limit ki value **1 se kam (decrement by 1)** ho jaati hai. Agar Hop Limit `0` ho jaye, toh router packet ko drop kar deta hai aur sender ko ICMPv6 "Time Exceeded" error bhej deta hai (taaki infinite routing loops na banein).

7. Source address (16 bytes):
